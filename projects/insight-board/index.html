01 · Research

Three people, three very different mornings

The same dashboard has to answer a quick "are we on track?" for a director, support a deep dive for an analyst, and give an account manager one number to repeat in a customer call. Each persona below lists the questions the design must answer before anything else.

02 · Information architecture

Seven areas, two levels deep, nothing hidden in a settings menu

The map is drawn from the navigation model itself. Overview is the landing page for everyone; the four metric areas share one filter bar; Reports and Alerts are where analysts and account managers do their saved work.

  • Global filters (date range, plan, region) live once in the top bar and persist across the four metric areas, so switching from Acquisition to Revenue never resets the question.
  • Reports hold saved views built from any metric area. A report is a filter set plus a layout, not a copy of the data, so it stays current.
  • Alerts are first-class pages, not a bell icon: each rule shows its history, its threshold and who gets notified.

03 · Wireframes

Low fidelity, real labels, decisions made early

Grey boxes settle hierarchy, reading order and density before colour or type can distract. The numbered pins mark the decisions that carried through to the final interface.

  1. 1One filter bar, fixed to the top, shared by every metric area. Export sits beside the filters so a PDF always matches what is on screen.
  2. 2Four KPI tiles, each with a sparkline and a comparison to the previous period. Never more than four; the fifth question belongs in a report.
  3. 3Charts stack as small multiples instead of sharing a dual axis, so sessions and conversions can be compared without a misleading second scale.
  4. 4Funnel steps show absolute counts and drop-off between steps, and every step name links to its definition.
  5. 5Reports are saved filter sets with a schedule and recipients. The definitions footnote travels with the export.

05 · Accessibility

Contrast you can check, not just claim

The table reads the dashboard's live CSS custom properties and computes each contrast ratio with the WCAG 2 relative-luminance formula. Switch the palette above and the numbers change with it.

Contrast ratios Default palette

Text pairs are held to AA for normal text (4.5:1). Chart marks and UI components are held to 3:1. Series that fall short are never the only encoding: bars carry direct value labels and the table repeats every number.

PairSwatchRatioTargetResult

Formula: (L1 + 0.05) / (L2 + 0.05), where L is relative luminance of each sRGB colour after gamma expansion. Values are read from getComputedStyle on the dashboard root, so they reflect the real rendered palette.

    Decisions baked into the UI

    • Visible focus rings. Every control shows a 2px ring on keyboard focus; the segmented controls move focus inside their own group with the arrow keys.
    • No colour-only encoding. Lines are labelled at the end, bars carry values, funnel steps print counts and drop-off, and trends pair an arrow with the sign.
    • Real table semantics. The segment table uses th scope="col" headers, right-aligned tabular figures and a scrolling wrapper rather than truncated cells on narrow screens.
    • Reduced motion respected. Transitions are wrapped in prefers-reduced-motion: no-preference, so nothing animates for people who have asked it not to.
    • One axis per chart. Sessions and conversions sit in stacked panels with a shared crosshair instead of a dual-axis chart, which is easy to misread.
    • Density is a preference, not a redesign. Compact mode changes spacing tokens only; reading order, labels and hit targets of at least 30px stay the same.
